System Overview

NetGuard IDS is an anomaly-based Network Intrusion Detection System using a 3-stage ensemble pipeline trained on CIC-IDS2017. It is designed for SOC analyst workflows: submit flow logs → get classified verdicts → label results → feed incremental retraining.

Techniques from Literature

  • Feature importance split — 42 required (RF Gini >1%) + 28 optional (median-imputed). Kotwal (2024) uses XGBoost >1% → 20 features.
  • RobustScaler — handles attack-traffic outliers better than MinMaxScaler.
  • VarianceThreshold — removes near-constant features before RF.
  • Median imputation — missing optional features use training median, not zero.
  • FAR & AMR — operationally meaningful for SOC analysts (Kotwal 2024, Bandarupalli).
  • Metadata exclusion — Timestamp, Flow ID, IPs dropped to prevent shortcut learning.
  • Analyst feedback loop — TP/FP/FN labels drive incremental retraining. SMOTE on training split only.

Why LSTM Autoencoder?

The LSTM-AE treats the 72-feature vector as a 72-step sequence, learning non-linear inter-feature dependencies that a feedforward AE misses. Pre-trained on NSL-KDD then fine-tuned on CIC-IDS2017 (transfer learning). HAST-IDS (CNN+LSTM) achieves F1 = 0.997 on flow sequences, validating deep sequence models for NIDS.

Limitation: without true pcap-level temporal sequences the LSTM advantage over a VAE is marginal. The anomaly score (reconstruction error vs p95 threshold) is the primary AE contribution here.
